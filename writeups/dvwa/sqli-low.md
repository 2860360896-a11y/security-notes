# DVWA SQL注入 Low 级别通关详解

## 1. 环境准备
- 靶场：DVWA (Damn Vulnerable Web Application)
- 难度：Low
- 测试工具：Burp Suite、浏览器

## 2. 漏洞原理
由于后端没有对用户输入的 ID 参数进行过滤，直接将其拼接到 SQL 查询语句中，导致攻击者可以构造恶意语句执行。

## 3. 测试过程
**步骤1**：正常访问，输入 `1`，页面正常回显用户信息。
**步骤2**：判断注入点，输入 `1'`，页面报错，说明存在单引号闭合的字符型注入。
**步骤3**：构造 payload 获取数据库信息。
- 测试字段数：`1' ORDER BY 2 #` （正常），`1' ORDER BY 3 #` （报错），得出字段数为 2。
- 联合查询爆库名：`1' UNION SELECT 1, database() #`
- 结果显示数据库名为：`dvwa`

## 4. 防御方案
使用 PDO 预处理语句（参数化查询），将代码与数据分离；同时对输入进行严格的类型检查。

## 5. 总结
这是我打通的第一关，理解了闭合符 `'` 和注释符 `#` 的作用。
